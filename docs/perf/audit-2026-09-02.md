# Convex scale and client-jank audit — 2026-09-02

## Scope and conclusion

The ledger read path is structurally safe for an unbounded history: every
growing collection is tenant-scoped and paginated, calendar/statistics totals
come from bounded rollups, and no Convex function calls `.collect()` on
`ledgerItems`. The 100,000-item transaction-budget suite passed on exact main
commit `8ba77137287fe37ae43fa63c2e775dfc1d19ac44` in GitHub Actions run
`33575881281`.

This audit found one client-side jank defect. `ConvexQueryCacheProvider` was
mounted, but application screens imported `useQuery` and `usePaginatedQuery`
from `convex/react`, bypassing the provider. All application reads now use the
drop-in hooks from `convex-helpers/react/cache`; only the session-key bootstrap
query intentionally runs before the cache provider. The cache is bounded,
account-scoped, memory-only, and expires idle subscriptions after five minutes.
It never persists ledger data or mutation arguments.

## Client render cost

- Growing lists use `FlashList`; the timeline supplies `getItemType` for its
  heterogeneous section and item rows.
- FlashList is pinned to `2.3.1`, which includes current scroll-position fixes.
  Timeline sticky headers hide their related source cell so iOS never paints a
  duplicate date row while retaining the user's scroll position.
- Expo SDK 57's static package map still recommends FlashList `2.0.2`, whose
  public props do not include `stickyHeaderConfig` or `hideRelatedCell`.
  FlashList `2.3.1` is JavaScript-only with unrestricted React/React Native
  peers, has passed both platform smokes, and is therefore explicitly excluded
  only from Expo's version-pin check rather than silently downgraded.
- `EntryRow` and the other hot row types are memoized.
- Calendar, category-drilldown, and deleted-entry lists now pass stable row,
  key, navigation, and load-more callbacks instead of rebuilding closures for
  every visible row.
- Amount search enables `customPagination` because its server query uses
  `mergedStream`; this preserves gapless page connections when loading more.
- A static regression test rejects application imports of Convex's uncached
  query hooks. Mutations, actions, connection state, and the pre-provider
  session bootstrap remain on `convex/react` by design.
- The eight-page ceiling and tablet selection reset when the active ledger
  changes, so a heavily browsed ledger cannot suppress pagination or leak a
  selected detail into the next ledger.

## Write path and rollups

All public mutations use the triggers-wrapped mutation helper. An item insert,
update, soft-delete, or restore updates day, month, and category-month rollups
inside the same transaction. Dashboard reads never sum the complete item
history on the client or in a query handler. `clientRequestId` idempotency stays
server-side and direct online writes do not create an on-device outbox.

`ROLLUP_SHARD_COUNT` is currently `1`. This is correct only while the frozen
eight-writer contention test remains within its no-sustained-conflict and
stable-p95/p99 thresholds. The repository has a guarded Tier-3 driver, but a
fresh dated result requires an explicitly identified isolated non-production
deployment plus a review of that exact Convex Health window. It must never run
against production.
